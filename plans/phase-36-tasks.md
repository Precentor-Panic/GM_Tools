## Grounding facts every task must respect (explorer report, 2026-08-09, file:line-cited)
- **Ops transport:** GM_Tools refuses to clobber an unapplied ops batch (`writeOpsFileChecked` throws `FoundryOpsInFlightError` → 409, `wf-mcp-server/lib/foundry-ops.mjs:67`); Foundry's 5s watcher applies, writes results FIRST, then overwrites ops to `[]`; GM_Tools polls 500ms/7s (`writeFoundryOps`, foundry-ops.mjs:106) and consumes/clears results. The quiet flush MUST queue+retry on 409, never blind-write.
- **v14 SHOWSTOPPER:** `Scene.create({background:{src}})` is silently ignored on v14 — background lives on the embedded **Level** doc (`updateEmbeddedDocuments("Level",[{_id:"defaultLevel0000","background.src":…}])`, proven `plans/wf-test-setup.md:124`). The deprecated *getter* still works (pull unaffected). 36.1 fixes create AND implements update via the Level doc.
- **Map-file gap:** `StagecraftAsset.foundryRef` = `{sceneUuid}` only — the pull DISCARDS `background.src` (`foundry-pull-ops.mjs:209,222`). 36.0 pins + 36.2 implements capturing it as additive `foundryRef.imagePath`; `source:'local'` files get `fs.copyFile` → `<foundrydata>/worlds/<world>/scenes-from-gmtools/` (deferred §3d(a), co-located repos).
- **Dirty predicate:** scenes have `updatedAt` + `touchSceneSafely` on element routes (server.mjs:2325–2409) but tray drop/remove/budget + stagecraft accept DON'T touch the scene; no `lastPushedAt` exists. Additive `stagedForFoundry` + `lastPushedAt` + the missing touch calls give `dirty = staged && updatedAt > lastPushedAt`.
- **Existing push slice:** `pushSceneToFoundry` (foundry-push-ops.mjs:70) = `create_scene` only, `mapSrc` required caller input, `foundrySceneRef` written back on ok; route `POST /api/foundry/push-scene` (server.mjs:1826). Reuse/extend — don't fork a second path.
- **Token positions** exist only as pulled facts (token-store, keyed by sceneUuid); a never-pushed scene has none → 36.2's roster tokens auto-cluster at scene center (flagged first-pass).
- **Module gaps fixed in 36.1:** compound token `actorUuid` (`Scene.<id>.Token.<id>.Actor.<id>` → emit base `Actor.<id>`, extractToken foundry-bridge.mjs:~262); legendary-actions `activation.type` loss (VERIFY extract-vs-mapper first — `item.system` is passed opaquely, so the omission may be Foundry-side data shape, fix at the true layer); playlists absent from `buildFoundryIndex`.
